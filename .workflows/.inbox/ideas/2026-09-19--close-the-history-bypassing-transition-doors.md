# Close The Transition Doors That Bypass History

Two exported entry points in `internal/task` can change a task's status without recording that it happened. `task.Transition` (`internal/task/transition.go:25-28`) is a package-level wrapper with no production caller anywhere — only its own tests exercise it. `StateMachine.Transition` (`internal/task/state_machine.go:35-66`) is exported but called only from `internal/task/apply_cascades.go:52,93` and the package's own tests. Neither appends a `TransitionRecord`, and neither sets the `Auto` flag on the `TransitionResult` it returns, so both hand back a result reading `auto=false` whatever actually produced the change.

That was harmless while nothing downstream read the flag. It stopped being harmless when `free-text-round-trip` task 2-8 landed: `TransitionResult.Auto` is now documented as mirroring the flag on the persisted `TransitionRecord`, and the `changed` table every status command prints reads straight off it. These two doors satisfy that documented contract only by accident — they return the zero value, which happens to be the right answer for a user-requested change and the wrong one for everything else.

The failure is latent but sharp. A future status-moving path — a new command, or the `migrate` writer, which already sidesteps CLI conventions elsewhere — wiring to either entry point would move a task's status, append no history row, and print `auto=false` for a change the system made on its own. An agent reading that output believes it requested a change it did not; a user running `tick show` finds a status with no transition behind it. It is the same class of defect task 2-8 closed on the other door, left open on this one.

The proposed shape is subtractive: delete the free `task.Transition` wrapper outright, since nothing calls it, and unexport `StateMachine.Transition` so that `ApplyUserTransition` and `ApplySystemTransition` are the only ways in. Both of those already stamp the flag and write the record from one value. The work touches `internal/task/transition.go`, `internal/task/state_machine.go`, and the tests in `internal/task/transition_test.go` and `internal/task/state_machine_test.go`, which currently call the exported forms directly and would move to the two surviving entry points.

Surfaced by the task reviewer on `free-text-round-trip-2-8`. That task was created by the phase-2 consolidation sweep and therefore ran after the phase's bank had drained, so the finding had no bank to be deposited into — it is captured here instead.
