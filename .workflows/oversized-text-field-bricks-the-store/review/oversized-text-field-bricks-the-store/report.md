# Implementation Review: Oversized Text Field Bricks The Store

**Plan**: oversized-text-field-bricks-the-store
**Verdict**: Pass

## Summary
The fix is delivered across all four phases and all 17 plan tasks. `tasks.jsonl` is read by the store and by doctor through one shared line reader (`internal/jsonl/lines.go`) with no per-line size limit and the store's pre-fix line definition preserved exactly; the beads importer drops its own ceiling while keeping its trim rule. Store load errors name the line and, where the line carries a string `id`, the task. `tick rebuild` parses before it touches `cache.db`, so a failed rebuild leaves the cache byte-for-byte intact. Doctor judges every line with the store's own decoder (`storage.DecodeTaskLine`), shares one scan outcome — failure included — with every check, fails an incomplete read in every line-consuming check, and withholds `tick rebuild` advice while the store cannot load. The 50,000-character description cap is enforced on create, update and migrate before anything is written, and migrate adopts the CLI's title rules. Per-task verification found no blocking issue and one stale subtest name, corrected in this session; the change-set verification measured §1–§8 end to end with a built binary against disposable stores and found nothing wrong. Linters (`golangci-lint`, `gofmt`) and `go vet` are clean, and the full suite (`go test ./... -count=1`) is green over the corrected tree.
