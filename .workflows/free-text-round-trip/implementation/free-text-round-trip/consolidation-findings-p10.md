# Consolidation Findings: Free Text Round Trip (Phase 10)

## Findings

### F1: blocked_by is the one list section whose positional narrowing no test pins
- **Class**: behaviour
- **Failure**: An agent runs `tick show <id> --field blocked_by.2` on a task with several blockers and is handed the whole blocker list, or the wrong blocker. Nothing fails: exit 0, the document parses, the count header agrees with the rows, so the agent acts on a blocker ID it never asked for — `tick dep remove` against the wrong edge, or the wrong blocker reported upstream. Noticed only later, as a dependency edited against a task nobody named. The behaviour is correct in the tree today (verified against a built binary: `--field blocked_by.2` returns the second blocker in toon, pretty and JSON); what is missing is anything that keeps it correct.
- **Evidence**:
  - `internal/cli/format.go:126` — the single pairing site `selectedItems(d.BlockedBy, d.Fields.Positions(fieldBlockedBy))`, introduced by 10-1 when it merged the three per-formatter narrowing sites into `TaskDetail.selectedSections` (`internal/cli/format.go:125-141`). Its four siblings are `format.go:127-130`.
  - Consumers of the unguarded field: `internal/cli/toon_formatter.go:79`, `internal/cli/pretty_formatter.go:187`, `internal/cli/json_formatter.go:133` — one silent break reaches all three formats.
  - `internal/cli/list_show_test.go:1085` `TestShowFieldPositions` is the only narrowing suite; its fixture (`list_show_test.go:1096-1107`) carries two children, three notes, two tags and two refs and **no blockers**, so every narrowing subtest covers a section other than `blocked_by`.
  - The only `blocked_by` positional coverage anywhere is negative or one-blocker: `internal/cli/list_show_test.go:1350` (out of range), `internal/cli/show_fields_test.go:518` (not bare), `internal/cli/show_fields_test.go:639` (accepted by `ValidatePositions`), `internal/cli/show_fields_test.go:671` (out of range). On a one-blocker fixture `blocked_by.1` is indistinguishable from the whole section.
  - Measured, in a scratch copy of the tree: replacing `d.Fields.Positions(fieldBlockedBy)` with `nil` at `format.go:126` leaves `go test ./internal/cli` green. The identical mutation on each of `fieldChildren`, `fieldTags`, `fieldRefs` and `fieldNotes` fails the package.
- **Proposed shape**: add a second blocker to `TestShowFieldPositions`' fixture and assert `blocked_by.2` narrows to it — in toon, mirroring "it narrows a table to one row" (`list_show_test.go:1159`), and in pretty, mirroring "it narrows a pretty children block" (`list_show_test.go:1264`). Production code is expected to stay untouched; if either assertion fails, that is the defect this finding was written against. Worth considering while the fixture is open: drive the per-section narrowing assertions from `showListSections` so a list section added to the registry without a line in `selectedSections` fails, the way `TestShowListSectionsMatchRegistry` (`show_fields_test.go:606`) already guards registry drift.
- **Bank**: reviewer entry on `free-text-round-trip-10-1` — confirmed against the final tree and re-measured. The site it names now sits in `selectedSections` rather than in the three formatters, and the hole survived the move.
