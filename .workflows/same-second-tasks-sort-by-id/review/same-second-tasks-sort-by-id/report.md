# Implementation Review: Same Second Tasks Sort By Id

**Plan**: same-second-tasks-sort-by-id
**Verdict**: Pass

## Summary

All 12 plan tasks across the three phases are delivered and hold against the specification. Every task record carries an explicit `seq`: it is assigned by create and by migrate imports, backfilled on read above the file's highest sequence, and numbered by `Store.Mutate` before every write. It is carried into a schema-v3 cache column. The list, ready and blocked clauses end on created, seq and task ID, so tie order is total under every query plan, and `--count 1` under a tie now returns the first-authored task. `tick show` orders children by created, seq and ID with no priority term, and orders blockers by a new dependency ordinal (declaration order), across all five detail-rendering sites. A read-only, warning-severity doctor check reports duplicate sequences with their line numbers. The README states the tiebreak and names the new check, and both sentences are pinned by prose tests. No task verifier or change-set section raised a blocking issue. The review raised three contained findings: a survival test that could not detect renumbering, doctor tests still describing a 10-check doctor, and CLAUDE.md still stating cache schema v2. All three were corrected in this session and the full suite is green. Nothing needs planning.
